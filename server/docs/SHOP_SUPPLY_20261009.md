# 商店与补给配置 · 1.4.1

入口：`start-desktop.bat` → 登录器顶部 **GM 工具** → **商店配置 / 补给管理**。当前包 `server/dist/win-x64-1.4.1`。本次不启动真实游戏，实机画面由用户验收。

## 实机证据与改动

用户 1.4.0 日志 `server-20261009-080827-47068.jsonl` 有 409 次 Handled、10 次 Unsupported。6700/6701 商店查询原来仅返回 4 字节空列表，6702/6703 商城返回 2 字节空列表；现由 `GmService.Shops/ShoppingMall/SingleShop/BuyGoods` 连接持久化配置。未处理的 1492（战舰头像，8 次）和 500（删除材料查询，2 次）并非商店请求，不在本次修复范围。

4702/4703 原来只有家园类型 20；当前存档内 44/46 关闭。1.4.0 生成模板时将 `CommonData.DisplayExt` 清空，丢失抓包中的背景与视频资源。现在保留安全的展示资源键，首次升级通过 `OperationsState.DisplayVersion` 开启三类本地补给，此后不覆盖 GM 的关闭选择。`LocalPool.BeginTime/EndTime` 同时约束展示、抽卡、买券及概率查询。

9.1 客户端静态检查发现补给标签受有效期、等级和隐藏状态控制；这些证据不能证明旧版家园入口不可见的唯一原因。实际画面和资源加载仍需复验，不将协议返回成功等同于实机成功。

## GM 与购买行为

- 15 个商店入口、192 个可发放目录商品。支持名称、开关、添加/移除、排序、每日北京时间 04:00 补货及立即补货。
- 6700、6702、6704、6708、6714 均有明确响应。游戏手动刷新返回无需刷新，不扣费；GM 保存推送 6701/6703。
- 购买在一个 SQLite 事务内检查余额与限购，发放奖励、扣款、累计购买次数及保存审计。溢出或背包不足整体回滚。金币奖励进入钱包，水晶不误作材料货币展示。
- 购买成功先推送更新后的商店，再返回购买结果并同步钱包和背包。限购、配置、补给开关重启后保留；重复 GM 补货请求不重置第二次。
- 补给页显示当前三类配置及开关状态，支持开放/结束时间、名称、价格、奖品权重与保底。仍采用本地自定义奖池，不同步官方当期活动。

商店商品 ID 来自用户 9.1 抓包，与本地参考 ExcelOutput 8.4 商品表及现有发放目录取交集；仅使用价格固定的商品，或第一次购买后即达限购的商品。价格和奖励尚未逐项与 9.1 客户端静态目录核验。商品协议不承载任意价格/奖励，GM 因此不提供随意改价或虚构商品 ID。尚未接入现实付费、自动开礼包、优惠券、全局限购和任选包；商城 27 提供本地支持的兑换商品子集，未复刻官方礼包。
