# 首关打完后提示前置未通关 · 1.3.6

> 后续 1.3.7 已纠正本页将 7703 FAIL 视作无害回包的判断。用户确认三关已结算，但返回任务因该 FAIL 中止；详见 [返回世界修复](PJMS_CURRENT_WORLD_20261009.md)。

## 实机现象与存档

用户确认 1.3.5 已可选择女武神并进入第一关，打完后提示“前置关卡尚未通关，无法进入该关卡”。
日志共 265 条请求：262 条 Handled，131、154、7702 各出现一次 Unsupported。
首次 43 开战成功并推送快照；45 结算只返回 8 字节的 46 错误响应，没有成功快照，随后另一条 43 也失败。

只读检查原存档：10101 的 Entries=1、Wins=0，仍保留 10101 的活动战斗，结算回执数为 0。体力为 74、金币为 0。客户端日志明确报错：

```text
Deserialize proto.StageEndRsp meet exception
No proto.StageEndStatus enum is mapped to the wire-value 0
```

日志、截图保存于 `evidence/lobby/user-client-11.jsonl`、`user-output-11.txt`、`user-settlement-11.png`。

## 根因与静态依据

当前协议模型来自旧参考描述符，`StageEndReqBody.EndStatus` 缺省为 None=0。9.1 的实际默认值为 WIN=1，并在胜利时省略此字段。之前测试全部显式写入 1，遗漏了这一客户端行为。

| 9.1 静态位置 | 行为 |
| --- | --- |
| `StageEndReqBody` 构造，`0x11f3f840` | `0x11f3f856` 将 end_status 所在的 `+0xd0` 初始化为 1 |
| 该消息的序列化函数，`0xf7bc1e0` | `0xf7bc337` 读取状态；与 1 相等时跳过 field 2，其他合法值 2/3/4 才显式写入 |
| `NetworkManager.GetStageEndReqBody`，`0xa72aed0` | 构造消息并写入上述状态字段 |
| `NetworkManager.RequestLevelEndReq`，`0xa72b9e0` | 序列化正文，再发送正文和签名 |

旧服务端将省略状态的胜利包解释为 0，拒绝结算；错误回复又原样写入 EndStatus=0，触发客户端枚举反序列化异常。首关未记入通关，因此下一关的前置检查仍失败。

静态证据与文件哈希位于 `settlement-static-proof.json` 和 `settlement-static/`。独立测试正文 `08F54E30003001300250D8AD03` 来自静态规则，包含首关 ID、挑战索引与时间，但省略 end_status；不是用户流量捕获。原日志仅记录请求长度。

## 服务端修复

`CampaignService.End` 仅在 `HasEndStatus=false` 时使用 StageWin=1。显式 0、5 等非法值仍拒绝；失败、全灭、退出的 2/3/4 语义不变。
错误响应仅回显合法状态，避免写入客户端无法解析的枚举值。既有事务继续同时提交奖励、通关进度和重试回执；重试不重复发奖，成功结算后可开始 10102。

本次还为日志中新出现的命令增加明确处理：

| 请求/响应 | 范围 |
| --- | --- |
| 131/132 `StageInnerDataReport` | 确认收到战斗统计；统计上报不会替代结算或发放奖励 |
| 154/155 `AddGoodfeel` | 好感度养成尚未实现；自有角色返回 FAIL，非自有角色返回 AVATAR_NOT_EXIST |
| 7702/7703 `PjmsGetCurWorld` | 本地没有开放 PJMS 世界，返回 FAIL，不虚构世界 ID |

这些消息以 `protocol/settlement.proto` 的最小字段投影独立生成；统计的未使用子消息保留为未知字段。命令和字段来自已有参考目录，新增处理均要求已认证会话。

## 验证与发布

新增回归先在旧代码上复现三项失败：缺省胜利被拒绝，以及两个非法枚举错误回复。修改后验证缺省胜利、存档重载、重试幂等性、第二关前置、非法状态、辅助响应及其无奖励副作用。
隔离 KCP 对比 32/64 位帧与进程重启；既有显式状态、失败/退出和副本领奖流程继续回归。最终数量记录见本页“最终结果”及 `VERIFICATION.txt`。

1.3.6 一体包位于 `dist/win-x64-1.3.6/`，包含原生登录器和服务端；原入口继续启动同包服务端。复制 1.3.5 的账号、配置和证书，保持 schema 3，不修改原始存档。
四角色沿用 `evidence/lobby/` 下的修改包、差异、验证记录和回滚脚本；1.3.5 角色归档至 `revisions/1.3.5/`。回滚基准仍为原始骨架，1.3.5 的故障对照另行记录。

## 用户复验

关闭旧游戏和登录器，通过根目录 `start-desktop.bat` 启动 1.3.6。之前那次结算失败未留下有效通关回执，需要重打一遍第一关，再检查结算、进入第二关及重登后的进度。
尚未过期的首关活动战斗会复用原有体力预扣；修复不直接伪造通关或补发未经结算的奖励。实机仍由用户进行，助手只做静态分析、只读日志检查及隔离测试。
