# 会话生命周期

## 连接与回收

`SessionRegistry` 用完整远端 IP:port 作为连接键，不能仅按 IP 关联多个客户端。
相同端点、相同 nonce 的重复握手复用 conv 并刷新活动时间；nonce 改变则关闭旧会话并分配新 conv。
达到 `maxSessions` 时拒绝新增，已存在的重复握手仍可恢复。默认 256 个会话、空闲 30 秒。
活动时间使用 `TimeProvider` 的单调计数器，系统时钟调整不会延长或缩短连接期限。
回收循环每秒执行；停止宿主时清空所有会话。

## 身份与分发

状态为 `Connected → Authenticated → Closed`。Authenticate 只允许从 Connected 执行，不能重绑账号或复活已关闭会话。
认证后才能调用玩家用例；Closed 清除 PlayerId。
每个会话的处理器调用、玩家用例、认证和关闭通过同一锁串行执行。

当前生产注册表为空，因此握手不会推进到 Authenticated。未来认证处理器需要验证服务端签发票据后绑定 UID。
`GamePacket.ClaimedUserId` 只是网络数据，不能覆盖会话身份。
未知消息返回内部 Unsupported 状态和空响应列表，不回客户端“成功”。

## 当前边界

未接入跨连接认证恢复、KCP 活动时间更新和已认证断线协议。
非握手 UDP 只计数，不刷新会话、不修改玩家。将来可靠传输验证数据归属后才能触碰会话。
nonce 目前用于兼容和去重，不是身份凭据或可用于公开网络的连接认证。
