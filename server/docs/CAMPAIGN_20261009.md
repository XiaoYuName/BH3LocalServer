## 事务与奖励规则

新增 schema 3：`player_campaign` 保存关卡、当前出击、任务/宝箱领取记录、材料和队伍；`stage_receipt` 按认证 UID 和请求指纹保存结算回执。原 schema 1/2 迁移逻辑不变。
`LobbyStore.Campaign` 在同一个 SQLite 写事务里更新大厅钱包、玩法状态和回执。会话 UID 决定写入账号，报文 UID 不参与选择存档。

相同关卡/队伍在 24 小时内重复开始返回同一预约，不重复扣体力；开始另一个合法关卡会替换未结算出击，旧体力不退。24 小时后的出击不可结算，可重新开始。
胜利发放目录定义的奖励，忽略客户端上报的金币、经验和掉落数量。已获得的挑战星不会再次发奖，重刷仍获得基础通关奖励。
失败、全灭、退出均关闭出击，消耗已预约体力，不发奖励、不推进任务。完全相同的结算重发返回原回执，不重复加钱或覆盖新出击。
任务与宝箱领奖先检查整批条件，再原子提交；重复领取返回具体错误。成功变更后推送主数据、关卡、任务、角色和装备快照。

关卡、前置、挑战/任务/宝箱奖励、升级表来源见 `Campaign/chapter-one.json` 的 sourceFiles 哈希。`tools/import_campaign.py` 可重新抽取。
本地规则：舰长基础通关经验等于关卡体力；基础金币和角色经验来自关卡表；每六分钟恢复一点体力，升级体力补充来自升级表。只实现确定奖励，不预告未导入的随机掉落池。

最终计数与文件哈希记录于 `evidence/lobby/VERIFICATION.txt`，四角色沿用原路径，1.2.4 交付已归档到 `evidence/lobby/revisions/1.2.4/`。

## 用户实机检查

1. 关闭旧登录器，使用原启动入口打开 1.3.0，登录已有本地账号。
2. 出击→主线第一章，从 1-1 开始，检查场景加载与角色操作。
3. 通关后检查金币、经验、挑战星和下一关；领取主线任务奖励。
4. 退出重登检查进度与材料，再测试第二关中途退出和重新进入。

如果客户端停止推进，日志中的 `game.campaign` 会记录 begin/end/mission-reward/act-reward、关卡、retcode 和奖励结果，不记录票据、sign_key 或完整签名。
`gameplayReady=false` 保留，表示全部玩法尚未完成；大厅已有用户实机通过记录。
