## 数据与协议

`CampaignState.Operations` 保存邮件、奖池、保底计数及日志，与钱包、背包在一个 SQLite 事务中写入。沿用 schema 4 的 JSON 扩展。管理写请求带独立 GUID 和请求内容摘要，同一请求重试返回原结果，不重复发放。抽卡使用持久化随机令牌及回执；同一抽取请求重放不扣款、不重抽。背包/余额超限时整个操作回滚。

GM 通过运行中的本地服务写库，不直接打开数据库；HTTP 仅接受回环客户端和本机 Host，写接口要求同源及专用请求头。提交后在 KCP 同步区推送钱包、角色、装备、补给状态；发送邮件追加 3808 通知。断线后可重新登录读取已保存状态。

邮件 3800–3810：分页列表、一键/指定领取、已读、删除、收藏及新邮件通知。附件发放与领取标记原子保存，重复领取无重复奖励；过期邮件不能领取，游戏内不会删除未领取附件或收藏邮件。GM 删除有独立确认。邮件不是向外部邮箱发送消息。

补给 4700–4709：抽取、展示、买券、记录、概率。新生成装备使用现有最大实例 ID 之后的值；角色绑定自己拥有的初始武器。原有库存 protobuf 未涉及字段继续保留。

协议结构由原有本地参考 DLL 导出，并对照当前抓包：3800 请求 `stop=9`；3802 空 key 列表表示一键领取；3803 回传已领取 key、合并附件及 `is_take_all`；3804/3805 为已读请求/回包。3801 的样式 1 和未领取计数也已补齐。4700/4701 的实际抓包确认抽卡类型、数量、随机令牌及奖励字段；4704/4705 是买券。证据位于 `evidence/lobby/gm-140`。
