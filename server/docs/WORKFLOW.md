# 实施与交付流程

入口见 [开发规范](DEVELOPMENT.md)，当前任务见 [STATUS](STATUS.md)。参考 115CN 的“证据 → 实现 → 自动验证 → 发布 → 实机”组织。

## 证据顺序

1. 确认 BH3 客户端版本、所用输入和现有实现。
2. 优先当前 9.1 请求、客户端读写点和协议定义，记录完整输入哈希。
3. 参考工程只提供分层和方法。旧版包、DNF 消息号与存档不直接迁移。
4. 证据不足的字段登记到专项，保留未知状态，不生成成功结论。

## 工作闭环

1. 在专项文档写清范围、当前入口、行为和验收输入。
2. 修改相应层；宿主中不塞入业务和存档 SQL。
3. 运行相关回归，再运行完整 `test.bat`。
4. 构建独立发布包，在临时配置、随机端口和空数据库上联调。
5. 验证正常退出、启动失败清理和重启恢复。
6. 更新 README、文档索引和 STATUS，只写已观察的结果。

## 发布与实机

用户已明确：后续实机联调由用户完成，除非用户另行明确要求助手联调。常规交付执行构建、隔离自动化测试和发布，向用户提供包与验收要点；不自动启动游戏客户端。

发布前停止目标服务，备份配置和玩家库；保留已有发布配置，不把测试库放入发布包。
本轮只建立并验证骨架，不自动修改登录器设置或启动客户端。
后续协议链接通后，按一组完整流程验证认证、大厅下一请求和重登恢复，再记录用户实机结果。
