# 商城与公告 · 1.4.2

## 问题与修复

用户 1.4.1 实机截图显示「商店异常，请联系客服」。日志中的 6706→6707 只有 2 字节的成功码，无充值商品；6703 只有 7 项替代兑换商品。SDK 公告红点 `/bh3_cn/combo/red_dot/list` 为 404，公告 HTML 仅含 title；客户端随后触发 12 秒加载超时。

- 6703 恢复真实采集的 179 项商城商品，保留分类锚点、图片配置与排序，使用本地购买次数和开放时间。普通商店及已有购买次数保留。首次升级恢复商城目录，之后遵从 GM 开关和商品列表。
- 6707 恢复 13 项水晶、礼包币和月卡商品；月卡状态使用本地存档，不复制官方账号的历史领取记录。
- 6731/6732、1494/1495、207/208 走本地模拟充值成功，并发送 6742 成功通知、11 余额、6707 商品和 6722 月卡状态。无真实支付、外部支付回调或银行操作。
- 水晶首购奖励只发一次；礼包币兑换校验金额、余额并原子提交；月卡每天 04:00（上海）刷新，领取重试不重复发放。
- 89 项商城商品有可核实的奖励映射（含服装）。服装持久化并同步角色服装列表，角色后续解锁时同样可见。
- 90 项只记录购买成功且不扣款：84 项新版本商品缺少物品映射，另 6 项需要自选/周期奖励或缺失物品定义。没有编造发货。GM「商店配置」明确显示待配奖状态，可把发放页面清单应用为该商品的奖励，也可恢复默认奖励。详见 `evidence/lobby/mall-142/catalog-coverage.json`。
- 公告返回本地实际内容，提供 SDK `jsapiready` 接口、初始化通知和关闭按钮；红点接口返回正常成功结构。这是本地公告，不冒充官方活动公告。

## 验证与边界

120 项分层测试通过（Protocol 12、Persistence 9、Game 84、Server 15）。发布包通过 485 项原生 KCP 检查，其中商城专项 44 项，覆盖两种 KCP 帧格式、充值、余额、月卡、防重复领取和进程重启。迁移后的整包 17 项检查通过（SDK 公告 1 项新增）。全部业务测试使用隔离账号与临时存档。

未启动用户游戏；公告 SDK 实际显示、商城资源及付款按钮的实际 UI 链路仍需用户在 1.4.2 实机复验。原生 KCP 测试证明已实现的命令和成功通知，并不证明所有 SDK 付款入口都已被真实客户端触发。商品覆盖范围为这次抓包的目录，不代表官方所有历史或未采集活动。
