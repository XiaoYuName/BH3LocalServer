# 崩坏 3 原生桌面登录器

参考 115CN 登录器的深色金色配色、顶部导航、左侧主视觉和右侧固定启动区，使用 C# / .NET 10 WinForms 与 GDI 重写。窗口不使用浏览器、Electron 或 WebView；发布版自带 Windows x64 运行时，不需要安装 Python 或 .NET。

## 启动

双击 `../server/dist/win-x64/Launcher/BH3.Launcher.exe`，也可以使用项目根目录的 `start-desktop.bat` 或 games 目录的 `启动崩坏3.bat`。原 `start.bat` 和 Python 版本保留。

1. 首页确认客户端路径，或选择 `BH3.exe`，点击“检查客户端”。
2. 舰长名称和 UID 是本地测试账号，可直接使用默认值。
3. “启动服务”自动运行随包服务器，再启动本地接口与 HTTP/HTTPS 代理，单独点击此按钮不会修改系统代理。
4. “启动游戏”在需要时启动服务、接管系统代理并运行客户端。证书未安装时，先用“安装本地证书”由 Windows 提示确认。客户端要求提升权限时由 Windows 显示 UAC。
5. “停止服务”或关闭登录器会恢复本次接管前的代理并释放监听端口。登录器重启时也会处理上次遗留的代理备份；若其他程序已修改代理则保留其配置。

## 页面与数据

- **开始游戏**：目录选择、本地账号、客户端检查、证书状态、服务启停和启动游戏。
- **运行记录**：实时日志、日志目录、诊断 ZIP 导出、恢复代理。
- **启动设置**：端口、系统代理、可选 WinHTTP、自定义服务端覆盖、首页背景。
- **版本信息**：版本与当前可用范围。

配置保存在 EXE 同目录 `Data/settings.json`，日志在 `Data/logs/`。默认端口为接口 TCP 20100、代理 TCP 8080、游戏 UDP 21000，均只监听本机。证书私钥用当前 Windows 用户 DPAPI 加密保存；可读取工作区已有本地 CA。WinHTTP 默认关闭，仅管理员可启用。

9.1 dispatch 已使用两份实际密文验证过的 AES-256 ECB / PKCS7 密钥，按 32 字节 ASCII 使用。生成的 dispatch 指向本地服，保留工作区缓存的 9.1 资源清单。代理仅将匹配的游戏域名和接口导向本地；资源下载放行。SDK 游戏公告仍可返回 HTML，这是客户端协议响应，不是登录器界面。

## 当前范围

本次重写包括 UI、配置、日志、证书、代理恢复、本地 SDK/dispatch 和进程管理。内置游戏服仍只有 UDP 握手，尚未实现完整 KCP 游戏逻辑，不能据此进入大厅。默认自动托管同包 Server，也可在设置中指定兼容 9.1 的外部游戏服 EXE，登录器会托管该进程并关闭内置握手入口。该外部服的玩法和实际客户端进入大厅未在本次验证中测试。

## 构建与验证

开发需要 .NET SDK 10.0.401（由 `global.json` 固定），Windows x64。在此目录运行：

```bat
build.bat
publish.bat
```

`build.bat` 编译并运行 9 项专项检查。`publish.bat` 调用统一发布流程，同时生成登录器与服务端，输出到 `../server/dist/win-x64/`。整包检查见 `../server/docs/BUNDLE_RELEASE_20261009.md`。源码在 `src/BH3.Launcher/`，资源在 `Resources/`。

检查覆盖真实密文往返、本地地址、代理路由边界、HTTP 分帧、代理恢复、DPAPI、实际 HTTP/HTTPS CONNECT/UDP 请求、端口冲突清理和配置读写。检查使用隔离数据目录与模拟代理存储，不安装根证书、不修改真实系统代理、不启动游戏。

界面另在本机 150% DPI 下检查了四个页面、设置保存、客户端检查、启动/停止服务与健康接口。发布前核对了原有九个文件的 SHA-256，原文件保持不变。

`verification/` 保存构建输出、测试报告、原版快照、差异和可复现的回滚记录。回滚脚本只接受一份交付包副本，不改动游戏客户端或当前安装目录。
